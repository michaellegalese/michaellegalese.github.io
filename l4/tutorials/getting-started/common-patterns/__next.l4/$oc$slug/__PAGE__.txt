3:T3f90,<h1>Common patterns</h1>
<p>Recipes for structures that come up again and again in legal rules. Each block runs as written; copy it into a file and adapt it. For what each keyword means exactly, follow the links to the <a href="/l4/reference">reference</a>.</p>
<hr>
<h2 id="records-and-choices">Records and choices</h2>
<p>A record groups facts about one thing; a list of choices names the cases something can be in. A choice can carry its own data.</p>
<pre><code class="language-l4">DECLARE Address
    HAS `street` IS A STRING
        `city`   IS A STRING

DECLARE Person
    HAS `name`    IS A STRING
        `age`     IS A NUMBER
        `address` IS AN Address

DECLARE Status IS ONE OF
    Active
    Suspended
    Terminated

DECLARE `Payment Status` IS ONE OF
    Pending
    Paid     HAS `amount` IS A NUMBER
    Rejected HAS `reason` IS A STRING

DECLARE `Legal Entity` IS ONE OF
    Individual  HAS `person`       IS A Person
    Corporation HAS `company name` IS A STRING
</code></pre>
<p>To act on each case, use <code>CONSIDER</code>. A case that carries data binds it to a name:</p>
<pre><code class="language-l4">DECLARE `Payment Status` IS ONE OF
    Pending
    Paid     HAS `amount` IS A NUMBER
    Rejected HAS `reason` IS A STRING

GIVEN payment IS A `Payment Status`
GIVETH A STRING
`payment description` MEANS
    CONSIDER payment
    WHEN Pending    THEN "Awaiting payment"
    WHEN Paid a     THEN CONCAT "Paid ", TOSTRING a
    WHEN Rejected r THEN CONCAT "Rejected: ", r

#EVAL `payment description` (Rejected "card declined")
</code></pre>
<p>See <a href="/l4/reference/types/DECLARE">DECLARE</a> and <a href="/l4/reference/control-flow/CONSIDER">CONSIDER</a>.</p>
<hr>
<h2 id="decisions">Decisions</h2>
<h3 id="requirements-as-a-checklist">Requirements as a checklist</h3>
<p>When a rule has several requirements, give each one a name in a <code>WHERE</code> block. The main condition then reads like the list in the source text, and each requirement can be traced and tested on its own.</p>
<pre><code class="language-l4">DECLARE Applicant
    HAS `age`             IS A NUMBER
        `citizenship`     IS A STRING
        `annual income`   IS A NUMBER
        `is disqualified` IS A BOOLEAN

GIVEN `the applicant` IS AN Applicant
GIVETH A BOOLEAN
DECIDE `the applicant is eligible` IF
        `the age requirement is met`
    AND `the citizenship requirement is met`
    AND `the income requirement is met`
    AND NOT `the applicant`'s `is disqualified`
    WHERE
        `the age requirement is met` MEANS
                `the applicant`'s `age` AT LEAST 18
            AND `the applicant`'s `age` LESS THAN 65

        `the citizenship requirement is met` MEANS
                `the applicant`'s `citizenship` EQUALS "citizen"
            OR  `the applicant`'s `citizenship` EQUALS "permanent resident"

        `the income requirement is met` MEANS
            `the applicant`'s `annual income` LESS THAN 40000
</code></pre>
<h3 id="exceptions-with-unless">Exceptions with UNLESS</h3>
<p>When the source says "unless" or "except where", use <code>UNLESS</code>. <code>p UNLESS q</code> means <code>p AND NOT q</code>, and <code>UNLESS</code> applies to everything before it.</p>
<pre><code class="language-l4">GIVEN `meets the age requirement` IS A BOOLEAN
      `has valid ID`              IS A BOOLEAN
      `is disqualified`           IS A BOOLEAN
GIVETH A BOOLEAN
DECIDE `is eligible` IF
            `meets the age requirement`
        AND `has valid ID`
    UNLESS  `is disqualified`
</code></pre>
<p>See <a href="/l4/reference/operators/UNLESS">UNLESS</a>.</p>
<h3 id="one-answer-from-several-cases">One answer from several cases</h3>
<p>For a value that depends on ranges or cases, <code>BRANCH</code> reads better than nested <code>IF ... ELSE IF</code>. The first condition that holds wins.</p>
<pre><code class="language-l4">GIVEN score IS A NUMBER
GIVETH A STRING
`grade` MEANS
    BRANCH
        IF score >= 90 THEN "A"
        IF score >= 80 THEN "B"
        IF score >= 70 THEN "C"
        IF score >= 60 THEN "D"
        OTHERWISE "F"

#EVAL `grade` 85
</code></pre>
<p>See <a href="/l4/reference/control-flow/IF">IF and BRANCH</a>.</p>
<hr>
<h2 id="calculations">Calculations</h2>
<h3 id="intermediate-values">Intermediate values</h3>
<p>Name the steps of a formula in <code>WHERE</code>, so each step shows up in an evaluation trace:</p>
<pre><code class="language-l4">DECLARE Loan
    HAS `principal`   IS A NUMBER
        `annual rate` IS A NUMBER
        `months`      IS A NUMBER

GIVEN loan IS A Loan
GIVETH A NUMBER
`monthly payment` MEANS
    p TIMES r TIMES factor DIVIDED BY (factor MINUS 1)
    WHERE
        p      MEANS loan's `principal`
        r      MEANS loan's `annual rate` DIVIDED BY 12
        n      MEANS loan's `months`
        factor MEANS EXPONENT (1 PLUS r) n

#EVAL `monthly payment` (Loan WITH `principal` IS 10000, `annual rate` IS 0.06, `months` IS 12)
</code></pre>
<h3 id="progressive-bands">Progressive bands</h3>
<p>For tax, fees or tiered pricing, where each part of a value is charged at its own rate: work out how much falls in each band, then add up. Each band takes only the part of the income inside its own range, so nothing is counted twice.</p>
<pre><code class="language-l4">GIVEN income IS A NUMBER
GIVETH A NUMBER
`tax owed` MEANS
         `amount in band 1` TIMES 0.10
    PLUS `amount in band 2` TIMES 0.20
    PLUS `amount in band 3` TIMES 0.40
    WHERE
        `band 1 limit` MEANS 20000
        `band 2 limit` MEANS 50000

        `amount in band 1` MEANS
            IF income &#x3C;= `band 1 limit` THEN income ELSE `band 1 limit`

        `amount in band 2` MEANS
            BRANCH
                IF income &#x3C;= `band 1 limit` THEN 0
                IF income &#x3C;= `band 2 limit` THEN income MINUS `band 1 limit`
                OTHERWISE `band 2 limit` MINUS `band 1 limit`

        `amount in band 3` MEANS
            IF income &#x3C;= `band 2 limit` THEN 0 ELSE income MINUS `band 2 limit`

#EVAL `tax owed` 60000
</code></pre>
<p>The result is <code>12000</code>: 10% of 20,000, plus 20% of 30,000, plus 40% of 10,000. Add a band by adding a limit and an <code>amount in band</code> definition.</p>
<h3 id="recursion">Recursion</h3>
<p>A definition can use itself, as long as it has a base case:</p>
<pre><code class="language-l4">GIVEN n IS A NUMBER
GIVETH A NUMBER
factorial n MEANS
    IF n &#x3C;= 1
    THEN 1
    ELSE n TIMES factorial (n MINUS 1)

#EVAL factorial 5
</code></pre>

<h2 id="lists">Lists</h2>
<p>The list functions (<code>all</code>, <code>any</code>, <code>filter</code>, <code>map</code>, <code>null</code>, <code>elem</code>, <code>count</code> and more) come from the prelude, so start with <code>IMPORT prelude</code>. <code>GIVEN x YIELD ...</code> is an unnamed function, used to say what to check or compute for each item.</p>
<pre><code class="language-l4">IMPORT prelude

DECLARE Person
    HAS `name` IS A STRING
        `age`  IS A NUMBER

`the people` MEANS LIST
    Person "Alice" 34,
    Person "Bob" 15,
    Person "Carol" 52

GIVEN people IS A LIST OF Person
GIVETH A BOOLEAN
`everyone is an adult` MEANS all (GIVEN p YIELD p's `age` >= 18) people

GIVEN people IS A LIST OF Person
GIVETH A BOOLEAN
`someone is a minor` MEANS any (GIVEN p YIELD p's `age` &#x3C; 18) people

GIVEN people IS A LIST OF Person
GIVETH A LIST OF Person
`only the adults` MEANS filter (GIVEN p YIELD p's `age` >= 18) people

GIVEN people IS A LIST OF Person
GIVETH A LIST OF STRING
`their names` MEANS map (GIVEN p YIELD p's `name`) people

GIVEN people IS A LIST OF Person
GIVETH A MAYBE Person
`the first person` MEANS
    CONSIDER people
    WHEN EMPTY                THEN NOTHING
    WHEN p FOLLOWED BY others THEN JUST p

#EVAL `their names` (`only the adults` `the people`)
#EVAL null `the people`
#EVAL elem 3 (LIST 1, 2, 3)
</code></pre>
<p>See <a href="/l4/reference/libraries/prelude">prelude</a> and <a href="/l4/reference/functions/YIELD">YIELD</a>.</p>

<h2 id="dates">Dates</h2>
<p>Date functions come from the <code>daydate</code> library. <code>Date</code> takes day, month and year; subtracting two dates gives the number of days between them.</p>
<pre><code class="language-l4">IMPORT daydate

`the start date`  MEANS Date 1 3 2025
`the expiry date` MEANS Date 31 12 2025

GIVEN `the first date`  IS A DATE
      `the second date` IS A DATE
GIVETH A NUMBER
`the number of days from` `the first date` `to` `the second date` MEANS
    `the second date` MINUS `the first date`

GIVEN `the date` IS A DATE
GIVETH A BOOLEAN
`has expired on` `the date` MEANS `the expiry date` `is before` `the date`

#EVAL `the number of days from` `the start date` `to` `the expiry date`
#EVAL `the start date` PLUS 30
#EVAL `has expired on` (Date 2 1 2026)
</code></pre>
<p>See <a href="/l4/reference/libraries/daydate">daydate</a>. For amounts of money in a currency, see the <a href="/l4/reference/libraries/currency">currency library</a>.</p>

<h2 id="obligations">Obligations</h2>
<p>The blocks in this section share the declarations in the first one. Run them together.</p>
<h3 id="obligation-permission-prohibition">Obligation, permission, prohibition</h3>
<pre><code class="language-l4">DECLARE Party IS ONE OF Seller, Buyer, Employee

DECLARE Action IS ONE OF
    `deliver goods`
    `pay invoice`
    `inspect goods`
    `disclose confidential information`
    `ship goods`
    `arrange pickup`
    `provide documentation`
    pay HAS amount IS A NUMBER

GIVETH A DEONTIC Party Action
`delivery obligation` MEANS
    PARTY Seller
    MUST `deliver goods`
    WITHIN 14
    HENCE FULFILLED
    LEST BREACH BY Seller BECAUSE "the goods were not delivered within 14 days"

GIVETH A DEONTIC Party Action
`inspection right` MEANS
    PARTY Buyer
    MAY `inspect goods`
    WITHIN 7

GIVETH A DEONTIC Party Action
`confidentiality clause` MEANS
    PARTY Employee
    SHANT `disclose confidential information`
    WITHIN 365
</code></pre>
<p>When <code>HENCE</code> or <code>LEST</code> is left out, a sensible default applies: for <code>MUST</code>, <code>HENCE FULFILLED</code> and <code>LEST BREACH</code>. A permission that is not used, or a prohibition respected until the deadline, ends as fulfilled.</p>
<h3 id="one-obligation-after-another">One obligation after another</h3>
<p><code>HENCE</code> can lead to the next obligation, so fulfilling one starts the next:</p>
<pre><code class="language-l4">GIVETH A DEONTIC Party Action
`sale contract` MEANS
    PARTY Seller
    MUST `deliver goods`
    WITHIN 14
    HENCE
        PARTY Buyer
        MUST `pay invoice`
        WITHIN 30
        HENCE FULFILLED
        LEST BREACH BY Buyer
    LEST BREACH BY Seller

#TRACE `sale contract` AT 0 WITH
    PARTY Seller DOES `deliver goods` AT 10
    PARTY Buyer DOES `pay invoice` AT 25
</code></pre>
<h3 id="a-condition-on-the-action">A condition on the action</h3>
<p><code>PROVIDED</code> adds a condition the action must meet. Here only a payment of at least the price counts:</p>
<pre><code class="language-l4">GIVEN `the price` IS A NUMBER
GIVETH A DEONTIC Party Action
`payment of at least the price` MEANS
    PARTY Buyer
    MUST pay amount PROVIDED amount >= `the price`
    WITHIN 30
    HENCE FULFILLED
    LEST BREACH BY Buyer

#TRACE `payment of at least the price` 100 AT 0 WITH
    PARTY Buyer DOES pay 80 AT 5
    PARTY Buyer DOES pay 120 AT 10
</code></pre>
<p>The payment of 80 does not count; the payment of 120 fulfils the obligation.</p>
<h3 id="obligations-in-parallel-and-alternatives">Obligations in parallel, and alternatives</h3>
<p><code>RAND</code> requires all of its obligations; <code>ROR</code> is satisfied by any one of them:</p>
<pre><code class="language-l4">GIVETH A DEONTIC Party Action
`delivery with documents` MEANS
        (PARTY Seller MUST `deliver goods` WITHIN 14 HENCE FULFILLED LEST BREACH BY Seller)
    RAND
        (PARTY Seller MUST `provide documentation` WITHIN 14 HENCE FULFILLED LEST BREACH BY Seller)

GIVETH A DEONTIC Party Action
`delivery options` MEANS
        (PARTY Seller MUST `ship goods` WITHIN 14 HENCE FULFILLED LEST BREACH BY Seller)
    ROR
        (PARTY Seller MUST `arrange pickup` WITHIN 7 HENCE FULFILLED LEST BREACH BY Seller)
</code></pre>
<p>See <a href="/l4/reference/regulative/PARTY">PARTY, MUST, MAY, SHANT</a> and <a href="/l4/reference/regulative/consequences">Deadlines and consequences</a>.</p>

<h2 id="mirroring-a-statute">Mirroring a statute</h2>
<p>To keep a rule readable side by side with the statute, <code>...</code> joins conditions with AND and <code>..</code> with OR, without repeating the keyword, and a quoted string inside the condition holds the statute's connecting words without changing the result:</p>
<pre><code class="language-l4">GIVEN `intentionally`                   IS A BOOLEAN
      `recklessly`                      IS A BOOLEAN
      `damages property`                IS A BOOLEAN
      `the property belongs to another` IS A BOOLEAN
GIVETH A BOOLEAN
DECIDE `commits criminal damage` IF
        "a person who without lawful excuse"
    ... `damages property`
    ... "belonging to another,"
    ... `the property belongs to another`
    ... "and does so"
    ...     `intentionally`
        OR  `recklessly`
</code></pre>
<p>See <a href="/l4/reference/operators#asyndetic-and-and-or">asyndetic AND and OR</a> for the operators, <a href="/l4/concepts/language-design/linguistic-syntax">Reading like the law</a> for a full worked statute, and <a href="/l4/reference/syntax#ditto">ditto</a> for <code>^</code>, which repeats the word above it in aligned conditions.</p>

<h2 id="tests-next-to-the-rules">Tests next to the rules</h2>
<p>Test each threshold on both sides:</p>
<pre><code class="language-l4">GIVEN age IS A NUMBER
GIVETH A BOOLEAN
DECIDE `is an adult` IF age AT LEAST 18

#ASSERT `is an adult` 18
#ASSERT NOT `is an adult` 17
#ASSERT `is an adult` 19
</code></pre>
<p><a href="/l4/tutorials/getting-started/testing-your-rules">Test your rules</a> covers <code>#ASSERT</code> and <code>#TRACE</code> in full.</p>

<h2 id="avoid-these-mistakes">Avoid these mistakes</h2>
<p>The <a href="/l4/reference/errors">error message reference</a> lists these and more, with the messages they produce.</p>
<h3 id="avoid-field-access-as-an-unbracketed-argument">Avoid: field access as an unbracketed argument</h3>
<p><code>count charity's `governors`</code> applies <code>count</code> to <code>charity</code> alone. Put the field access in parentheses:</p>
<pre><code class="language-l4">IMPORT prelude

DECLARE Charity HAS `governors` IS A LIST OF STRING

GIVEN charity IS A Charity
GIVETH A BOOLEAN
`has governors` MEANS count (charity's `governors`) > 0
</code></pre>
<p>See <a href="/l4/reference/errors#field-access-as-an-argument">Field access as an argument</a>.</p>
<h3 id="avoid-if-without-else">Avoid: IF without ELSE</h3>
<p>Every <code>IF</code> needs an <code>ELSE</code>, because the expression must have a value in every case: <code>IF condition THEN "yes" ELSE "no"</code>. With several cases, use <code>BRANCH ... OTHERWISE</code>. See <a href="/l4/reference/errors#if-without-else">IF without ELSE</a>.</p>
<h3 id="avoid-misaligned-fields">Avoid: misaligned fields</h3>
<p>All fields of a record line up under the first one:</p>
<pre><code class="language-l4">DECLARE Person
    HAS `name`  IS A STRING
        `age`   IS A NUMBER
        `email` IS A STRING
</code></pre>
<p>Indenting <code>`age`</code> less or more than <code>`name`</code> is a parse error.</p>
