20:Tf9b,<h1>Embed rules in a website</h1>
<p>Add one <code>&#x3C;script></code> tag to your website so that your visitors' browser AI assistants can run your deployed rules, through <a href="https://webmachinelearning.github.io/webmcp/">WebMCP</a>. An eligibility checker or a clause evaluator on your page becomes a set of tools the visitor's agent can call, with no back end of your own.</p>
<p><strong>Before you start:</strong> a deployment (<a href="/l4/tutorials/deploying-rules/exporting-rules-for-deployment">Deploy your rules</a>), and access to your site's HTML. For permissions and self-hosted addresses, see <a href="/l4/tutorials/legalese-cloud">Choose an integration</a>.</p>
<hr>
<h2 id="the-script">The script</h2>
<pre><code class="language-html">&#x3C;script
  src="https://api.legalese.cloud/.webmcp/embed.js"
  data-org="{orgSlug}"
  data-scope="insurance-premium"
  data-tools="auto"
  data-api-key="sk_..."
>&#x3C;/script>
</code></pre>
<p>The <strong>Integrate</strong> dialog of a deployment in VS Code shows this tag filled in for that deployment.</p>
<table>
<thead>
<tr>
<th>Attribute</th>
<th>Meaning</th>
</tr>
</thead>
<tbody>
<tr>
<td><code>src</code></td>
<td>The script, served by Legalese Cloud or by your own jl4-service.</td>
</tr>
<tr>
<td><code>data-org</code></td>
<td>Your organization on Legalese Cloud.</td>
</tr>
<tr>
<td><code>data-scope</code></td>
<td>The deployments to offer: <code>*</code> for all, a deployment name, or several names separated by commas.</td>
</tr>
<tr>
<td><code>data-tools</code></td>
<td>Which kinds of tools to register (see below). Default: <code>auto</code>.</td>
</tr>
<tr>
<td><code>data-api-key</code></td>
<td>A Legalese Cloud API key that may run the rules.</td>
</tr>
</tbody>
</table>
<h2 id="which-tools-are-registered">Which tools are registered</h2>
<p><code>data-tools</code> chooses kinds of tools, not individual rules:</p>
<table>
<thead>
<tr>
<th>Value</th>
<th>Registers</th>
</tr>
</thead>
<tbody>
<tr>
<td><code>rules</code></td>
<td>One tool per exported rule, which runs that rule directly.</td>
</tr>
<tr>
<td><code>rule-tools</code></td>
<td>Three search tools: <code>search_rules</code>, <code>get_rule_schema</code> and <code>evaluate_rule</code>.</td>
</tr>
<tr>
<td><code>file-tools</code></td>
<td><code>list_files</code>, <code>read_file</code>, <code>search_identifier</code> and <code>search_text</code>, to read the L4 source.</td>
</tr>
<tr>
<td><code>auto</code></td>
<td><code>rules</code> when the scope has at most 10 exported rules, otherwise <code>rule-tools</code>.</td>
</tr>
<tr>
<td><code>all</code></td>
<td>All of the above.</td>
</tr>
</tbody>
</table>
<p>Values can be combined: <code>data-tools="rules,file-tools"</code>. With <code>auto</code>, the tools follow your redeploys without any change to the page. The search tools do the same job as the all-deployments MCP server's <code>search_rules</code>, <code>get_schema</code> and <code>evaluate</code>, under different names; see <a href="/l4/tutorials/legalese-cloud/ai-agents#tool-names-in-webmcp">Connect an AI agent</a>.</p>
<h2 id="the-api-key">The API key</h2>
<ol>
<li>Open the <a href="https://legalese.cloud">Legalese Cloud console</a>.</li>
<li>Create an API key with only the <code>l4:rules</code> and <code>l4:evaluate</code> permissions, limited to the deployment you are embedding.</li>
<li>Put your organization in <code>data-org</code> and the key in <code>data-api-key</code>.</li>
</ol>
<p>The key is part of your page's HTML, so anyone can read it. Treat it as a publishable key, not a secret: leave out <code>l4:read</code>, which the browser does not need, and replace the key if it is misused. See <a href="/l4/tutorials/legalese-cloud#api-keys-and-permissions">API keys and permissions</a>.</p>
<h2 id="check-it">Check it</h2>
<p>Open a page with the script in a browser with a WebMCP-aware assistant. Your rules appear among its tools; calling one runs the deployed rule and returns its result.</p>
