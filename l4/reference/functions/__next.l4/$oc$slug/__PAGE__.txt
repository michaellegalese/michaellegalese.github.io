3:Tb84,<h1>Functions</h1>
<p>A function takes inputs and computes a result from them. In L4 each rule is a function: <code>GIVEN</code> names and types its inputs, <code>GIVETH</code> states the type of its result, and <code>DECIDE</code> or <code>MEANS</code> gives the expression that computes it. A function without inputs is a named value.</p>
<pre><code class="language-l4">GIVEN age IS A NUMBER
GIVETH A BOOLEAN
DECIDE `is an adult` age IF age >= 18
</code></pre>
<h2 id="pages">Pages</h2>
<ul>
<li><a href="/l4/reference/functions/DECIDE">DECIDE</a>: define a value or a function, including <code>DECIDE … IF</code> and functions written as several clauses</li>
<li><a href="/l4/reference/functions/GIVEN">GIVEN and GIVETH</a>: declare the inputs and the result type</li>
<li><a href="/l4/reference/functions/MEANS">MEANS</a>: define without <code>DECIDE</code></li>
<li><a href="/l4/reference/functions/LET">LET and WHERE</a>: local definitions before or after an expression</li>
<li><a href="/l4/reference/functions/YIELD">YIELD</a>: functions without a name</li>
<li><a href="/l4/reference/functions/AKA">AKA</a>: more than one name for the same function, value, type or section</li>
</ul>
<h2 id="mixfix-functions">Mixfix functions</h2>
<p>A function's name does not have to come first. In a <strong>mixfix</strong> function, the <code>GIVEN</code> inputs are placed between the words of the name, so a call reads like a sentence:</p>
<pre><code class="language-l4">GIVEN mom IS A STRING
      dad IS A STRING
      kid IS A STRING
GIVETH A STRING
mom and dad `have a baby named` kid MEANS
    CONCAT "mother: ", mom, ", father: ", dad, ", child: ", kid

#EVAL "alice" and "bob" `have a baby named` "carol"
</code></pre>
<ul>
<li>A call uses the same word order as the definition.</li>
<li>Inputs can come before, between or after the words, so a function can be infix (<code>applicant `is entitled to` benefit</code>) or postfix (<code>n squared</code>).</li>
<li>A word of the name can be a quoted identifier with spaces, such as <code>`is entitled to`</code>, so the words can be legal phrases.</li>
<li>The words that are not inputs act as keywords of that function. When a call mixes inputs and words, L4 finds the function by those words.</li>
</ul>
<p>A mixfix function cannot be written as <a href="/l4/reference/functions/DECIDE#several-clauses">several clauses</a>; use <code>CONSIDER</code> in its body.</p>
