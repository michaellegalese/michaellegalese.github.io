1f:T32a8,<h1>@nlg</h1>
<p><code>@nlg</code> gives a definition its wording in natural language.
<code>l4 render</code>, <code>l4 nlg</code> and the editor read that wording in place of the name.</p>
<pre><code class="language-l4">GIVEN x IS A NUMBER, y IS A NUMBER
GIVETH A NUMBER
@nlg the greater of %x% and %y%
`the greater of` x y MEANS IF x >= y THEN x ELSE y
</code></pre>
<p><code>#EVAL `the greater of` 3 7</code> reads "the greater of 3 and 7".</p>
<ul>
<li><strong>To fix wording in a document:</strong> <a href="/l4/tutorials/natural-language-functions/fix-wording-with-nlg">Fix wording with @nlg</a></li>
<li><strong>To write rules that read well:</strong> <a href="/l4/tutorials/natural-language-functions/optimising-natural-language-generation">Make rules read like law</a></li>
<li><strong>Example:</strong></li>
</ul>
<pre><code class="language-l4-file">-- An `@nlg` sentence on a mixfix function, and what reads it.
-- See the `@nlg` section of the syntax reference.

GIVEN a IS A NUMBER, b IS A NUMBER
GIVETH A NUMBER
`the lower of` a `and` b @nlg the smaller of %a% and %b%
  MEANS IF a AT MOST b THEN a ELSE b

GIVEN price IS A NUMBER
GIVETH A NUMBER
`the price we charge` price MEANS `the lower of` price `and` 100

#EVAL `the lower of` 840 `and` 160
</code></pre>
<p>Text in square brackets after a name is a short form: <code>DECIDE `the limit` [the statutory limit] IS 5</code>.</p>
<h2 id="slots">Slots</h2>
<p><code>%name%</code> is filled with the call's argument.</p>
<ul>
<li>An input with spaces in its name keeps its backticks: <code>%`the amount`%</code>.</li>
<li>A slot has no spaces inside. <code>% amount %</code> is plain text, and L4 warns.</li>
<li>An input with no slot is not dropped. It follows the sentence: "the threshold is passed with 5".</li>
</ul>
<p>To write <code>%</code> or <code>]</code> as itself, put a backslash before it:</p>
<table>
<thead>
<tr>
<th>You write</th>
<th>You get</th>
</tr>
</thead>
<tbody>
<tr>
<td><code>10\%and\%20</code></td>
<td><code>10%and%20</code></td>
</tr>
<tr>
<td><code>[rate \] per unit]</code></td>
<td><code>rate ] per unit</code></td>
</tr>
<tr>
<td><code>[see note \[3\] here]</code></td>
<td><code>see note [3] here</code></td>
</tr>
<tr>
<td><code>\\</code></td>
<td><code>\</code></td>
</tr>
</tbody>
</table>
<p>You need this only where a <code>%</code> touches a word: <code>a 5% levy on %amount%</code> works as written.
Take care with <code>%word%</code>: if <code>word</code> names an input, L4 fills it in and nothing warns.</p>
<h2 id="where-to-put-it">Where to put it</h2>
<table>
<thead>
<tr>
<th>Where</th>
<th>Whose wording it is</th>
</tr>
</thead>
<tbody>
<tr>
<td>On its own line, between the <code>GIVEN</code> or <code>GIVETH</code> and the rule</td>
<td>The rule's sentence</td>
</tr>
<tr>
<td>After the rule's name: <code>DECIDE `is large` @nlg …</code></td>
<td>The rule's sentence</td>
</tr>
<tr>
<td>After an input named in the head: <code>`is large` amount @nlg …</code></td>
<td>The rule's sentence</td>
</tr>
<tr>
<td>On an <code>AKA</code> name</td>
<td>The rule's sentence</td>
</tr>
<tr>
<td>After an input in the <code>GIVEN</code>, or indented under it</td>
<td>That input's</td>
</tr>
<tr>
<td>After a field, or under it</td>
<td>That field's</td>
</tr>
<tr>
<td>On its own line above a <code>GIVEN</code></td>
<td>Not the rule's</td>
</tr>
</tbody>
</table>
<ul>
<li><strong>Trailing a line, it describes that line. On its own line, it describes what follows.</strong> Fields and inputs are the exception: an annotation under one describes that one.</li>
<li><strong>Under the last input, field or <code>ASSUME</code>, the column decides.</strong> Indented past the <code>GIVEN</code>, <code>DECLARE</code> or <code>ASSUME</code> keyword, it describes that item. At the keyword's column or left of it, it describes what comes next. One extra space turns a rule's sentence into an input's wording, and nothing warns.</li>
<li><strong>After an enum whose last value has no fields,</strong> a line at the margin belongs to that value. Put the next rule's sentence after its name instead.</li>
<li><strong>Empty or duplicated:</strong> an empty <code>@nlg</code> is ignored with a warning. Two wordings in one language on one thing warn, and neither is used.</li>
<li><strong>In the head and above it:</strong> the one above is the rule's sentence, and the one on the input is that input's wording.</li>
<li><strong>A head that repeats an input</strong> takes the input from the head, so a wording in the <code>GIVEN</code> labels nothing.</li>
</ul>
<h2 id="how-it-reads">How it reads</h2>
<table>
<thead>
<tr>
<th>You annotate</th>
<th>It reads</th>
</tr>
</thead>
<tbody>
<tr>
<td>A rule</td>
<td>The sentence heads the rule and the body follows. Every call reads as the sentence.</td>
</tr>
<tr>
<td>A rule that calls itself, or an imported one</td>
<td>The sentence stands in for the body.</td>
</tr>
<tr>
<td>An input</td>
<td>Its label in a <code>WITH</code> call: <code>… where the amount is x</code>.</td>
</tr>
<tr>
<td>A field</td>
<td>After its owner: <code>@nlg date of birth</code> reads "the employee's date of birth".</td>
</tr>
<tr>
<td>A <code>BOOLEAN</code> field</td>
<td>On its own, with no owner, so write a whole statement.</td>
</tr>
</tbody>
</table>
<ul>
<li><strong>In a rule's own sentence,</strong> an input of a built-in type reads as a blank, <code>[x]</code>. An input of your own type reads as the rule's body calls it, such as "the application kind".</li>
<li><strong>A <code>WITH</code> call</strong> reads the sentence, then each argument by name: "the smaller of a and b where a is price and b is 100".</li>
<li><strong>A call reads the sentence of the definition it resolved to,</strong> not of another definition with the same name.</li>
<li><strong>A unit of time after a slot agrees with the number:</strong> "%n% months" reads "1 month" for 1.</li>
<li><strong><code>l4 nlg</code> writes literal dates as dates:</strong> <code>Date 16 7 2025</code> reads <code>16 July 2025</code>. A date that does not exist, such as <code>Date 31 2 2025</code>, stays a call.</li>
</ul>
<h2 id="when-a-slot-gets-brackets">When a slot gets brackets</h2>
<p>A sentence's own words can read as part of what fills its slot.
So a slot gets brackets when two things hold: the sentence goes on after the slot, and what fills it has no word to close it.</p>
<p>The sentence goes on after a slot when its words or another of its slots come after it.
With <code>@nlg %a%, %b%</code> on <code>comma</code>, <code>`comma` (NOT (`fb` p)) q</code> reads "(it is not the case that fb for p), [q]".
A slot at the end of a sentence has nothing after it, so it gets no brackets.
With <code>@nlg %a% is told %b%</code> on <code>told</code>, and <code>@nlg %p% is shown</code> on <code>shown</code>, <code>`told` p (NOT (`shown` q))</code> reads "[p] is told it is not the case that [q] is shown".</p>
<p>These have no closing word. Each example is in <code>l4 render</code>, where <code>shown</code> and <code>told</code> have the sentences above and <code>fb</code> has none.</p>
<table>
<thead>
<tr>
<th>What fills the slot</th>
<th>You write</th>
<th>It reads</th>
</tr>
</thead>
<tbody>
<tr>
<td>An <code>OR</code> or an <code>AND</code></td>
<td><code>`shown` (p OR q)</code></td>
<td>"(p or q) is shown"</td>
</tr>
<tr>
<td>A denial</td>
<td><code>`shown` (NOT (`fb` p))</code></td>
<td>"(it is not the case that fb for p) is shown"</td>
</tr>
<tr>
<td>An <code>IMPLIES</code></td>
<td><code>`shown` (p IMPLIES q)</code></td>
<td>"(p implies q) is shown"</td>
</tr>
<tr>
<td>A call with no sentence that ends with one of these</td>
<td><code>`shown` (`fb` (p AND q))</code></td>
<td>"(fb for p and q) is shown"</td>
</tr>
<tr>
<td>A call with a sentence whose last slot holds one</td>
<td><code>`shown` (`told` p (NOT (`fb` q)))</code></td>
<td>"([p] is told it is not the case that fb for q) is shown"</td>
</tr>
</tbody>
</table>
<p><code>l4 nlg</code> brackets the same slots, with names in backticks: <code>`shown` (TRUE OR FALSE)</code> reads "(<code>TRUE</code> or <code>FALSE</code>) is shown".
It also brackets an <code>IF</code>: <code>`shown` (IF TRUE THEN FALSE ELSE TRUE)</code> reads "(if <code>TRUE</code> then <code>FALSE</code> else <code>TRUE</code>) is shown".
<code>l4 render</code> moves a call into the branches of an <code>IF</code> instead.</p>
<p>Wording can still read two ways in these cases:</p>
<ul>
<li><strong>A denial of one condition in <code>l4 render</code></strong> reads "p is false" and gets no brackets, so <code>`shown` (NOT p)</code> reads "p is false is shown".</li>
<li><strong>The slot at the end of a sentence</strong> can run on into what follows the sentence: <code>((`told` p (NOT (`fb` q))) OR r) IMPLIES r</code> reads "[p] is told it is not the case that fb for q or r implies r".</li>
<li><strong>A sentence that ends with its slot, in <code>l4 nlg</code>:</strong> with <code>@nlg it is shown that %x%</code> on <code>shown that</code>, <code>(`shown that` TRUE) AND FALSE</code> and <code>`shown that` (TRUE AND FALSE)</code> both read "it is shown that <code>TRUE</code> and <code>FALSE</code>".</li>
<li><strong>A condition given to a call with no sentence</strong> gets no brackets: <code>NOT (p OR (`fb` (q AND r)))</code> reads "neither p nor fb for q and r".</li>
</ul>
<p>If a rule reads two ways because of one of these, give the condition a rule of its own, with a sentence, and call that.</p>
<h2 id="limits">Limits</h2>
<ul>
<li><strong>An <code>ASSUME</code>d function has no named inputs,</strong> so it has no slots, and a call reads as its name and arguments. Use a <code>BOOLEAN</code> field or a rule instead.</li>
<li><strong>A function passed on, or named without being called,</strong> reads as its name. In <code>filter even xs</code>, <code>even</code> reads <code>even</code>.</li>
<li><strong>A sentence inside another call is spliced in without brackets,</strong> so nested calls can read alike: with <code>@nlg %a% doubled</code> on <code>dbl</code>, <code>`f2` 2 (`dbl` 3)</code> and <code>`dbl` (`f2` 2 3)</code> both read "<code>f2</code> with 2 and 3 doubled". Set slots off with words that cannot be part of an argument, and read the output of nested calls. A sentence that ends with a condition is the exception: see <a href="#when-a-slot-gets-brackets">When a slot gets brackets</a>. Arithmetic is bracketed, and so is anything beside it that does not say where it ends: "10 minus (5 minus 2)", "(5 doubled) minus 2", "twice (5 minus 2)", "(f2 for 2 and x) − 3".</li>
<li><strong>A function with no sentence</strong> reads as its pattern: <code>`_ LESS _` with 100 and 20</code>.</li>
</ul>
<h2 id="several-languages">Several languages</h2>
<p>Tag each wording with its language, and ask for one with <code>--lang</code>:</p>
<pre><code class="language-l4">GIVEN amount IS A NUMBER
GIVETH A BOOLEAN
DECIDE `is large` @nlg:en the amount %amount% is large
                  @nlg:he %amount% עולה על הסף
  IF amount GREATER THAN 100
</code></pre>
<pre><code class="language-console">$ l4 nlg --lang he mymodule.l4
$ l4 render --format html --lang he mymodule.l4 -o mymodule.he.html
</code></pre>
<p>The Render tab in VS Code has a language menu when a file has wordings in more than one language.</p>
<ul>
<li><strong>L4 does not translate.</strong> It picks among the wordings you wrote.</li>
<li><strong>Regions match.</strong> <code>--lang he</code> reads a <code>he-IL</code> wording, and <code>--lang he-IL</code> reads a <code>he</code> one. An exact match comes first.</li>
<li><strong>A missing wording falls back</strong> to the rule's default: the one in the module's language, otherwise the first in the file.</li>
<li><strong>The square-bracket form cannot be tagged.</strong></li>
<li><strong>A word glued to the colon is a tag.</strong> <code>@nlg:the employee pays</code> has the tag <code>the</code>. L4 warns when nothing backs a tag as a language. Leave a space after the colon to keep it as text.</li>
</ul>
<p><strong><code>@lang he</code></strong> on a line of its own means every untagged <code>@nlg</code> in the module is Hebrew. It applies to the whole file.</p>
<ul>
<li>A module that declares nothing is <code>en</code>, so <code>@lang en</code> is not needed, and L4 hints that it can go.</li>
<li>Declare the language of a module that is not English: it sets <code>&#x3C;html lang=…></code>, right-to-left <code>dir</code> and the Akoma Ntoso language.</li>
<li>If two <code>@lang</code> lines disagree, the last one is used, and L4 warns.</li>
</ul>
<p><strong>L4's own words,</strong> such as "is equal to", "if" and "with", follow <code>--lang</code> where L4 has a table for the language. Hebrew is the only one. It is small and keeps English word order, so have a Hebrew speaker read the output. A word with no entry stays English, and <code>l4 nlg</code> names it on stderr.</p>
