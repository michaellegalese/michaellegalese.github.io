1f:T2849,<h1>Cheat sheet</h1>
<p>This page is a quick translation guide for developers coming from Python, JavaScript/TypeScript, Java, Haskell, SQL, or other languages. Find the construct you already know in the left columns, then look right for the L4 equivalent.</p>

<td><code>PLUS</code>, <code>MINUS</code>, <code>TIMES</code>, <code>DIVIDED BY</code></td>
<td><code>capital PLUS capital TIMES rate</code></td>
</tr>
</tbody>
</table>
<h2 id="l4-has-no">L4 Has No...</h2>
<p>L4 is a pure functional language designed for legal specifications. Several constructs familiar from imperative languages are deliberately absent.</p>
<table>
<thead>
<tr>
<th>Missing Construct</th>
<th>Why</th>
<th>What to Use Instead</th>
</tr>
</thead>
<tbody>
<tr>
<td><strong>Assignment / mutation</strong></td>
<td>All values are immutable. No side effects means no hidden state changes, which is critical for auditable legal reasoning.</td>
<td><code>MEANS</code> to bind names to expressions.</td>
</tr>
<tr>
<td><strong>Loops</strong> (<code>for</code>, <code>while</code>)</td>
<td>Iteration implies mutable state.</td>
<td>Recursion, or <code>map</code>/<code>filter</code>/<code>all</code>/<code>any</code> from the prelude.</td>
</tr>
<tr>
<td><strong>Null / nil / None</strong></td>
<td>The "billion dollar mistake." Missing values must be handled explicitly.</td>
<td><code>MAYBE</code> type with <code>NOTHING</code> and <code>JUST</code>. Pattern match with <code>CONSIDER</code>.</td>
</tr>
<tr>
<td><strong>Exceptions</strong></td>
<td>Thrown exceptions break referential transparency and make reasoning about code unreliable.</td>
<td><code>MAYBE</code> or <code>EITHER</code> types to represent failure as data.</td>
</tr>
<tr>
<td><strong>Semicolons / braces</strong></td>
<td>L4 uses layout-sensitive syntax (like Python and Haskell).</td>
<td>Indentation determines block structure.</td>
</tr>
<tr>
<td><strong>Implicit coercion</strong></td>
<td>No silent type conversions. Types must match explicitly.</td>
<td><code>TOSTRING</code> for explicit conversion.</td>
</tr>
<tr>
<td><strong>Mutable variables</strong></td>
<td>See assignment above. There is no <code>let x = 1; x = 2</code>.</td>
<td>Each <code>MEANS</code> or <code>WHERE</code> binding is a permanent definition.</td>
</tr>
<tr>
<td><strong>Return statements</strong></td>
<td>Every construct is an expression that produces a value.</td>
<td>The last (or only) expression in a definition is its value.</td>
</tr>
</tbody>
</table>
<p>These omissions are by design. Legal rules must be deterministic, traceable, and auditable. Pure functional semantics guarantee that the same inputs always produce the same outputs, with no hidden dependencies.</p>
