3:T135e,<h1>EVENT</h1>
<p>An event records that a party did an action at a time. A list of events is what a regulative rule is evaluated against: it decides which duties are fulfilled or breached.</p>
<h2 id="syntax">Syntax</h2>
<pre><code class="language-text">PARTY party DOES action AT time        -- in a #TRACE
EVENT party action time                -- as a value, for EVALTRACE
GIVEN e IS AN EVENT party action       -- as a type, for an input
</code></pre>
<table>
<thead>
<tr>
<th>Part</th>
<th>Type</th>
<th>Meaning</th>
</tr>
</thead>
<tbody>
<tr>
<td><code>party</code></td>
<td>the party type</td>
<td>who acted</td>
</tr>
<tr>
<td><code>action</code></td>
<td>the action type</td>
<td>what they did</td>
</tr>
<tr>
<td><code>time</code></td>
<td><code>NUMBER</code></td>
<td>when, on the rule's timeline</td>
</tr>
</tbody>
</table>
<h2 id="example">Example</h2>
<pre><code class="language-l4">DECLARE Person IS ONE OF Seller, Buyer
DECLARE Action IS ONE OF
  delivery
  payment HAS amount IS A NUMBER

GIVETH A DEONTIC Person Action
`sale contract` MEANS
  PARTY Seller
  MUST delivery
  WITHIN 3
  HENCE
    PARTY Buyer
    MUST payment 100
    WITHIN 7

-- Events in a #TRACE
#TRACE `sale contract` AT 0 WITH
  PARTY Seller DOES delivery AT 2
  PARTY Buyer DOES payment 100 AT 5

-- The same events as values, for EVALTRACE
#EVAL EVALTRACE `sale contract` 0 (LIST (EVENT Seller delivery 2), (EVENT Buyer (payment 100) 5))
</code></pre>
<p><code>EVALTRACE</code> takes the rule, the start time and the list of events, and returns the rule's state after them; see <a href="/l4/reference/regulative/DEONTIC#evaluation">DEONTIC: Evaluation</a>.</p>
<h2 id="how-events-are-read">How events are read</h2>
<ul>
<li>Events are read in order, and each moves the clock to its time.</li>
<li>An event by the rule's party whose action matches the rule fulfils it (or, for a prohibition, breaches it).</li>
<li>An event by another party, or with another action, is skipped; only its time counts.</li>
<li>An event after a deadline shows that the deadline has passed, and the rule moves on to <code>LEST</code> (or, for <code>MAY</code> and <code>SHANT</code>, <code>HENCE</code>); see <a href="/l4/reference/regulative/consequences#within">Deadlines and consequences</a>.</li>
</ul>
<h2 id="waituntil">WAITUNTIL</h2>
<p><code>WAITUNTIL time</code> is an event that matches no party and no action. Use it to let time pass without anyone acting, so that a deadline runs out:</p>
<pre><code class="language-l4">DECLARE Person IS ONE OF Seller, Buyer
DECLARE Action IS ONE OF delivery

GIVETH A DEONTIC Person Action
`delivery duty` MEANS
  PARTY Seller
  MUST delivery
  WITHIN 3

#TRACE `delivery duty` AT 0 WITH
  WAITUNTIL 10
</code></pre>
<p>This gives a breach: the deadline at 3 passed with no delivery.</p>
<h2 id="event-as-a-type">EVENT as a type</h2>
<p><code>EVENT</code> names the type of events as well as the function that makes one.
Written as a type it takes the type of the parties and the type of the actions, so a rule can take an event as an input and read it with <code>CONSIDER</code>, and another rule can build an event and hand it on.
The time of an event is always a <code>NUMBER</code>.</p>
<pre><code class="language-l4">DECLARE Person IS ONE OF Seller, Buyer
DECLARE Action IS ONE OF
  delivery
  payment HAS amount IS A NUMBER

GIVEN e IS AN EVENT Person Action
GIVETH A NUMBER
`when it happened` e MEANS
  CONSIDER e
  WHEN EVENT party action time THEN time

GIVEN who IS A Person
GIVETH A NUMBER
`when it was delivered` who MEANS `when it happened` (EVENT who delivery 2)

#EVAL `when it was delivered` Seller
</code></pre>
<p>This gives <code>2</code>.</p>
<p>A type of your own that is also called <code>EVENT</code> and takes two parameters is ambiguous with the built-in one wherever it is named; see <a href="/l4/reference/errors#several-definitions-with-the-same-name">Several definitions with the same name</a>.</p>
<h2 id="event-and-export">EVENT and @export</h2>
<p>A rule published with <code>@export</code> cannot take an <code>EVENT</code> as an input or give one back as its result, because a request has no way to write one.
The same goes for a <code>LIST OF</code> events or a <code>MAYBE OF</code> an event.
<code>l4 check</code> reports an error at the <code>@export</code> line and the service will not deploy the file; see <a href="/l4/reference/errors#an-export-that-takes-or-returns-an-event">An @export that takes or returns an EVENT</a>.
An <code>EVENT</code> that the rule builds or reads inside its body is not affected.</p>
