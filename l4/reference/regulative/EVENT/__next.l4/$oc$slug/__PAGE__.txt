3:Tce1,<h1>EVENT</h1>
<p>An event records that a party did an action at a time. A list of events is what a regulative rule is evaluated against: it decides which duties are fulfilled or breached.</p>
<h2 id="syntax">Syntax</h2>
<pre><code class="language-text">PARTY party DOES action AT time        -- in a #TRACE
EVENT party action time                -- as a value, for EVALTRACE
</code></pre>
<table>
<thead>
<tr>
<th>Part</th>
<th>Type</th>
<th>Meaning</th>
</tr>
</thead>
<tbody>
<tr>
<td><code>party</code></td>
<td>the party type</td>
<td>who acted</td>
</tr>
<tr>
<td><code>action</code></td>
<td>the action type</td>
<td>what they did</td>
</tr>
<tr>
<td><code>time</code></td>
<td><code>NUMBER</code></td>
<td>when, on the rule's timeline</td>
</tr>
</tbody>
</table>
<h2 id="example">Example</h2>
<pre><code class="language-l4">DECLARE Person IS ONE OF Seller, Buyer
DECLARE Action IS ONE OF
  delivery
  payment HAS amount IS A NUMBER

GIVETH A DEONTIC Person Action
`sale contract` MEANS
  PARTY Seller
  MUST delivery
  WITHIN 3
  HENCE
    PARTY Buyer
    MUST payment 100
    WITHIN 7

-- Events in a #TRACE
#TRACE `sale contract` AT 0 WITH
  PARTY Seller DOES delivery AT 2
  PARTY Buyer DOES payment 100 AT 5

-- The same events as values, for EVALTRACE
#EVAL EVALTRACE `sale contract` 0 (LIST (EVENT Seller delivery 2), (EVENT Buyer (payment 100) 5))
</code></pre>
<p><code>EVALTRACE</code> takes the rule, the start time and the list of events, and returns the rule's state after them; see <a href="/l4/reference/regulative/DEONTIC#evaluation">DEONTIC: Evaluation</a>.</p>
<h2 id="how-events-are-read">How events are read</h2>
<ul>
<li>Events are read in order, and each moves the clock to its time.</li>
<li>An event by the rule's party whose action matches the rule fulfils it (or, for a prohibition, breaches it).</li>
<li>An event by another party, or with another action, is skipped; only its time counts.</li>
<li>An event after a deadline shows that the deadline has passed, and the rule moves on to <code>LEST</code> (or, for <code>MAY</code> and <code>SHANT</code>, <code>HENCE</code>); see <a href="/l4/reference/regulative/consequences#within">Deadlines and consequences</a>.</li>
</ul>
<h2 id="wait-until">WAIT UNTIL</h2>
<p><code>`WAIT UNTIL` time</code> is an event that matches no party and no action. Use it to let time pass without anyone acting, so that a deadline runs out:</p>
<pre><code class="language-l4">DECLARE Person IS ONE OF Seller, Buyer
DECLARE Action IS ONE OF delivery

GIVETH A DEONTIC Person Action
`delivery duty` MEANS
  PARTY Seller
  MUST delivery
  WITHIN 3

#TRACE `delivery duty` AT 0 WITH
  (`WAIT UNTIL` 10)
</code></pre>
<p>This gives a breach: the deadline at 3 passed with no delivery.</p>
<p><code>EVENT</code> is both the name of the events' type and the function that makes one. Use it to make events; it cannot be written as the type of a <code>GIVEN</code> input.</p>
