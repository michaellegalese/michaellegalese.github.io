1e:T18a5,<h1>Standard libraries</h1>
<p>The standard libraries are L4 files that ship with every <code>l4</code> binary, the editor extension and Legalese Cloud. They are written in L4 and add functions for lists, dates, money, legal entities and more. Nothing from them is available until you <code>IMPORT</code> it, not even the prelude.</p>
<p>Functions built into the language, such as <code>TOSTRING</code>, <code>CONCAT</code> or <code>FETCH</code>, need no import: see <a href="/l4/reference/builtins">Built-in functions</a>.</p>
<h2 id="libraries">Libraries</h2>
<h3 id="core">Core</h3>
<ul>
<li><a href="/l4/reference/libraries/prelude">prelude</a>: lists, MAYBE and EITHER values, pairs and dictionaries.</li>
<li><a href="/l4/reference/libraries/math">math</a>: <code>exp</code>, logarithms, square roots and trigonometry that give <code>NOTHING</code> instead of failing on bad input.</li>
</ul>
<h3 id="dates-and-time">Dates and time</h3>
<ul>
<li><a href="/l4/reference/libraries/daydate">daydate</a>: build, compare and shift dates; weekdays, ISO weeks, months and leap years. Its page also covers <code>date-compat</code>, the older <code>DATE d m y</code> spelling.</li>
<li><a href="/l4/reference/libraries/time">time</a>: time of day without a date or time zone, in 24-hour or AM/PM form.</li>
<li><a href="/l4/reference/libraries/datetime">datetime</a>: a date, a time and a time zone together, compared across time zones.</li>
<li><a href="/l4/reference/libraries/timezone">timezone</a>: constants such as <code>SGT</code> and <code>EST</code> for IANA time zone names.</li>
<li><a href="/l4/reference/libraries/excel-date">excel-date</a>: Excel date serials and <code>DATEDIF</code>, <code>DAYS360</code>, <code>YEARFRAC</code>, <code>EDATE</code>, <code>EOMONTH</code>, <code>WORKDAY</code> and <code>NETWORKDAYS</code>.</li>
</ul>
<h3 id="money-and-finance">Money and finance</h3>
<ul>
<li><a href="/l4/reference/libraries/currency">currency</a>: amounts in whole minor units (cents) with ISO 4217 currency codes.</li>
<li><a href="/l4/reference/libraries/holdings">holdings</a>: cap tables, vesting, convertible notes and SAFEs, liquidation preferences and valuations.</li>
<li><a href="/l4/reference/libraries/actus">actus</a>: ACTUS financial contract types, events, day count conventions and schedules.</li>
</ul>
<h3 id="legal-entities-and-places">Legal entities and places</h3>
<ul>
<li><a href="/l4/reference/libraries/legal-persons">legal-persons</a>: names, addresses, identity documents, age and legal capacity, corporate entities and beneficial ownership.</li>
<li><a href="/l4/reference/libraries/jurisdiction">jurisdiction</a>: ISO 3166 country and subdivision codes, with checks and conversions.</li>
</ul>
<h3 id="ai">AI</h3>
<ul>
<li><a href="/l4/reference/libraries/llm">llm</a>: call Anthropic, OpenAI or OpenRouter models over HTTP.</li>
</ul>
<h2 id="import">IMPORT</h2>
<p><code>IMPORT</code> makes the definitions of another L4 file available in the current file. Put the <code>IMPORT</code> lines at the top of the file, before the first <code>§</code> section, one module per line. An <code>IMPORT</code> below a section heading is ignored without a warning: the names it should bring in are then reported as <a href="/l4/reference/errors#i-could-not-find-a-definition-for-the-identifier">not defined</a>.</p>
<p><strong>Example:</strong></p>
<pre><code class="language-l4-file">-- IMPORT examples

-- One module per line, at the top of the file.
IMPORT prelude
IMPORT math
IMPORT daydate

-- A name with a hyphen goes in backticks.
IMPORT `legal-persons`

-- prelude: list functions
#EVAL sum (LIST 1, 2, 3)

-- math: functions that give NOTHING instead of failing
#EVAL sqrt 16
#EVAL sqrt (0 - 1)

-- daydate: dates
#EVAL `the day after` (Date 31 12 2024)

-- legal-persons: age on a given date
#EVAL `age in years` (Date 15 3 1990) (Date 1 1 2025)
</code></pre>
<pre><code class="language-l4">IMPORT prelude
IMPORT daydate
IMPORT `legal-persons`
</code></pre>
<h3 id="module-names">Module names</h3>
<ul>
<li>A module is named by its file name without <code>.l4</code>: <code>IMPORT daydate</code> loads <code>daydate.l4</code>.</li>
<li>A name with a hyphen goes in backticks: <code>IMPORT `excel-date` </code>, <code>IMPORT `legal-persons` </code>, <code>IMPORT `date-compat` </code>. Without them, <code>IMPORT excel-date</code> is a parse error ("unexpected -").</li>
<li><code>IMPORT</code> takes a module name, not a path or a quoted string. <code>IMPORT "helpers.l4"</code> is a parse error, and a folder in front of the name is ignored: <code>IMPORT `rules/helpers` </code> looks for <code>helpers.l4</code>.</li>
</ul>
<h3 id="what-an-import-gives-you">What an import gives you</h3>
<ul>
<li>Every top-level definition of the imported file: its types, constructors, functions and constants.</li>
<li>Nothing is imported for you. A file that uses <code>map</code>, <code>sum</code> or <code>fromMaybe</code> needs <code>IMPORT prelude</code> like any other library.</li>
<li>Import each library you use by name. The definitions a library imports for itself also reach your file, but do not count on it: <code>IMPORT datetime</code>, for example, does not give you <code>Date</code>; that needs <code>IMPORT daydate</code>.</li>
</ul>
<h3 id="where-modules-are-found">Where modules are found</h3>
<p>For <code>IMPORT helpers</code>, L4 uses the first of these that exists:</p>
<ol>
<li><code>helpers.l4</code> in your project's root folder, or in the folder of the file that writes the <code>IMPORT</code>.</li>
<li>The standard library built into the <code>l4</code> you are running. It needs no files on disk and always matches that <code>l4</code>.</li>
</ol>
<p>So a file of your own with the name of a standard library, such as <code>prelude.l4</code> beside your rules, is used instead of the standard one. Operators and library developers can change the search with the <code>JL4_LIBRARY_PATH</code> environment variable; <a href="/l4/reference/libraries/resolution">How IMPORT finds libraries</a> gives the full order, what Legalese Cloud does, and the warning shown when two different copies of a module are visible. When nothing is found, the error is <a href="/l4/reference/errors#module-not-found">Module not found</a>.</p>
