3:T21e4,<h1>Types</h1>
<p>Every value in L4 has a type, and the type checker makes sure each rule is given and returns values of the right types.
L4 has a few built-in types, and <code>DECLARE</code> makes new ones: records, enumerations and synonyms.
Types are usually inferred, but writing them in <code>GIVEN</code> and <code>GIVETH</code> makes rules easier to read.</p>
<h2 id="pages">Pages</h2>

<li><a href="/l4/reference/types/ASSUME">ASSUME</a>: a name with a type and no definition</li>
<li><a href="/l4/reference/types/for-all">FOR ALL</a>: type variables in the type of an <code>ASSUME</code></li>
<li><a href="/l4/reference/types/coercions">Coercions</a>: converting between types (<code>TOSTRING</code>, <code>TONUMBER</code>, <code>TODATE</code>, <code>AS STRING</code> and others)</li>
</ul>

<td><code>NUMBER</code></td>
<td>exact numbers, whole or fractional: <code>42</code>, <code>-17</code>, <code>3.14</code>, <code>5.4%</code> (= <code>0.054</code>), <code>100_000</code></td>

<td><code>TRUE</code> and <code>FALSE</code></td>

<td>a calendar date, made with <code>Date 15 1 2025</code> from <a href="/l4/reference/libraries/daydate">daydate</a>, or parsed with <code>TODATE</code></td>
</tr>
<tr>

<td>a time of day, without a date or time zone; see <a href="/l4/reference/libraries/time">time</a></td>
</tr>
<tr>
<td><code>DATETIME</code></td>
<td>a point in time with a time zone; see <a href="/l4/reference/libraries/datetime">datetime</a></td>
</tr>
</tbody>
</table>
<ul>
<li>Arithmetic on <code>NUMBER</code> is exact: <code>10 / 4</code> is <code>2.5</code>, not a rounded value.</li>
<li>In a number, underscores between digits are ignored: <code>100_000</code> is <code>100000</code>. A number must start with a digit and must not end with an underscore.</li>
<li><code>TRUE</code> and <code>FALSE</code> are written in capitals.</li>
</ul>

-- List literal syntax

`second list` MEANS 1 FOLLOWED BY 2 FOLLOWED BY 3 FOLLOWED BY EMPTY

#EVAL `first list`
#EVAL `second list`
</code></pre>

<p>| <code>MAYBE a</code>    | <code>JUST 42</code> when there is a value, <code>NOTHING</code> when there is none |</p>
<pre><code class="language-l4-file">-- Example: Maybe type usage
-- Demonstrates optional values with JUST and NOTHING

`value is present` MEANS JUST OF 42
`value is absent` MEANS NOTHING

`get the value or default to zero` MEANS
  CONSIDER `value is present`
  WHEN JUST OF x THEN x
  WHEN NOTHING THEN 0

#EVAL `get the value or default to zero`
</code></pre>
<p>|
| <code>EITHER a b</code> | <code>LEFT "error"</code> or <code>RIGHT 42</code>                                  |</p>
<pre><code class="language-l4-file">-- Example: Either type usage
-- Either represents a choice: LEFT for errors, RIGHT for success values

-- Declare a result with explicit EITHER type
ASSUME `api result` IS AN EITHER STRING NUMBER

-- Create specific Either values
`error case` MEANS LEFT OF "Error occurred"
`success case` MEANS RIGHT OF 42

-- Pattern match to handle both cases
GIVEN result IS AN EITHER STRING NUMBER
`handle the result` result MEANS
  CONSIDER result
  WHEN LEFT OF err THEN CONCAT "Error: ", err
  WHEN RIGHT OF val THEN CONCAT "Success: ", TOSTRING val

#EVAL `handle the result` `error case`
#EVAL `handle the result` `success case`
</code></pre>
<p>|</p>
<p>L4 has no null: a value that may be missing has a <code>MAYBE</code> type, and <a href="/l4/reference/control-flow/CONSIDER">CONSIDER</a> handles both cases.
Functions on these types, and the <code>PAIR</code> and <code>Dictionary</code> types, are in the <a href="/l4/reference/libraries/prelude">prelude</a>.</p>
<h2 id="records-and-enumerations">Records and enumerations</h2>
<p>A record has named fields; an enumeration has a fixed list of values, each of which can carry fields. Both are made with <a href="/l4/reference/types/DECLARE">DECLARE</a>.
Examples:</p>
<pre><code class="language-l4-file">-- Example: Record type declaration
-- Demonstrates product types with named fields

DECLARE Person
  HAS `full name` IS A STRING
      age         IS A NUMBER

-- Example: Creating a person record
`the applicant` MEANS Person WITH
  `full name` IS "John Doe"
  age         IS 30

#EVAL `the applicant`'s `full name`
#EVAL `the applicant`'s age
</code></pre>
<p>,</p>
<pre><code class="language-l4-file">-- Example: Enum type declaration
-- Demonstrates sum types with named constructors

DECLARE Color IS ONE OF
  Red
  Green
  Blue

-- Example usage
`my favorite color` MEANS Red

`name of the color` MEANS
  CONSIDER `my favorite color`
  WHEN Red   THEN "red"
  WHEN Green THEN "green"
  WHEN Blue  THEN "blue"

#EVAL `name of the color`
</code></pre>
<p>.</p>
<h2 id="functions">Functions</h2>
<p>A function is a value too. Its type is written <code>FUNCTION FROM Type1 AND Type2 TO Result</code>, so a function can be an input of another function.
Example:</p>
<pre><code class="language-l4-file">-- Example: Function type
-- Demonstrates function type signature

GIVEN x IS A NUMBER
      y IS A NUMBER
GIVETH A NUMBER
add x y MEANS x PLUS y

#EVAL add 5 3
</code></pre>
<p>.</p>
<h2 id="type-parameters-and-inference">Type parameters and inference</h2>
<p>A function or a type can work for any type, with a type parameter (<code>GIVEN a IS A TYPE</code>; see <a href="/l4/reference/functions/GIVEN#type-parameters">GIVEN and GIVETH</a>).
Example:</p>
<pre><code class="language-l4-file">-- Example: Polymorphic function
-- Demonstrates generic types that work with any type

GIVEN a IS A TYPE
      list IS A LIST OF a
GIVETH A NUMBER
`length of list` list MEANS go 0 list
  WHERE
    go acc l MEANS
      CONSIDER l
      WHEN EMPTY THEN acc
      WHEN x FOLLOWED BY xs THEN go (acc + 1) xs

#EVAL `length of list` (LIST 1, 2, 3)
#EVAL `length of list` (LIST "a", "b", "c")
</code></pre>
<p>.</p>
<p>When <code>GIVETH</code> or an input's type is left out, L4 infers it.
Example:</p>
<pre><code class="language-l4-file">
GIVEN x IS A NUMBER
      y IS A NUMBER
`add two numbers` x y MEANS x PLUS y
</code></pre>
<p>.</p>
