1e:T2099,<h1>llm</h1>
<p>Calls large language models from L4: Anthropic's Claude, OpenAI, or any model on OpenRouter. Import it with <code>IMPORT llm</code>.</p>
<p>Each call sends one user message and gives back the provider's reply exactly as it arrives: the response body, a JSON text in a STRING. Take the answer out of it with <code>JSONDECODE</code> (see <a href="#reading-the-reply">Reading the reply</a>).</p>
<p><strong>Example:</strong></p>
<pre><code class="language-l4-file">-- llm example: a model answers a question of judgment, an L4 rule decides.
IMPORT prelude
IMPORT llm

-- The part of an Anthropic reply this file needs.
-- JSONDECODE ignores the other fields.
DECLARE `reply block` HAS
  text IS A STRING

DECLARE `Anthropic reply` HAS
  content IS A LIST OF `reply block`

GIVEN `raw reply` IS A STRING
GIVETH A MAYBE STRING
`the text of` `raw reply` MEANS
  CONSIDER `decoded reply`
  WHEN RIGHT reply THEN
    CONSIDER reply's content
    WHEN EMPTY THEN NOTHING
    WHEN block FOLLOWED BY rest THEN JUST (block's text)
  WHEN LEFT problem THEN NOTHING
  WHERE
    GIVETH AN EITHER STRING `Anthropic reply`
    `decoded reply` MEANS JSONDECODE `raw reply`

-- The question put to the model.
GIVEN `the notice` IS A STRING
GIVETH A STRING
`the question about` `the notice` MEANS
  CONCAT "Answer YES or NO and nothing else. Is this notice written in a professional tone? ", `the notice`

-- Asks Claude. This needs ANTHROPIC_API_KEY and network access,
-- so the file defines it but does not evaluate it.
GIVEN `the notice` IS A STRING
GIVETH A MAYBE STRING
`the verdict of the model on` `the notice` MEANS
  CONSIDER ENV "ANTHROPIC_API_KEY"
  WHEN JUST key THEN `the text of` (callClaude key (`the question about` `the notice`))
  WHEN NOTHING THEN NOTHING

-- The rule takes the model's answer as an input,
-- so it can be tested without calling a model.
GIVEN `the notice was given in time` IS A BOOLEAN
      `the verdict of the model` IS A MAYBE STRING
GIVETH A BOOLEAN
DECIDE `the notice is valid` IF
      `the notice was given in time`
  AND `the verdict of the model` EQUALS JUST "YES"

#EVAL `the text of` "{\"id\":\"msg_1\",\"content\":[{\"type\":\"text\",\"text\":\"YES\"}]}"
#EVAL `the notice is valid` TRUE (JUST "YES")
#EVAL `the notice is valid` TRUE NOTHING
</code></pre>
<h2 id="configuration">Configuration</h2>
<ul>
<li><strong>API keys.</strong> The <code>call...</code> functions take the key as their first input; read it with the built-in <code>ENV</code> so it stays out of your file. <code>queryLLM</code> and <code>queryLLMWithDefaults</code> read the environment variables <code>OPENROUTER_API_KEY</code>, <code>OPENAI_API_KEY</code> and <code>ANTHROPIC_API_KEY</code> themselves.</li>
<li><strong>Network.</strong> The calls use the built-in <code>POST</code>, so every evaluation makes a real HTTPS request and needs network access. Where L4 runs in safe mode, as it does in the browser, the request is refused with an error. See <a href="/l4/reference/builtins/http-json">HTTP and JSON</a>.</li>
</ul>

<h2 id="reading-the-reply">Reading the reply</h2>
<p>The reply is the provider's JSON. Declare records for the fields you need and decode into them with <code>JSONDECODE</code>; fields you do not declare are ignored.</p>
<ul>
<li>Anthropic puts the text in <code>content</code>, a list of blocks that each have a <code>text</code> field: <code>{"content": [{"type": "text", "text": "..."}]}</code>.</li>
<li>OpenAI and OpenRouter put it in <code>choices</code>, a list whose items have a <code>message</code> with a <code>content</code> field: <code>{"choices": [{"message": {"content": "..."}}]}</code>.</li>
</ul>
<p>The example file decodes an Anthropic reply in <code>`the text of`</code>.</p>
<h2 id="keeping-judgment-and-rules-apart">Keeping judgment and rules apart</h2>
<p>A model is good at questions of judgment, such as whether a notice is written in a professional tone. L4 is good at applying rules to the answers. Keep the two apart:</p>
<ul>
<li>Write the rule with the model's answer as an input (<code>GIVEN</code>), not as a call inside it. The rule can then be tested with <code>#EVAL</code> by passing answers directly, and it reads the same whoever, or whatever, supplies the answer.</li>
<li>Ask for an answer in a fixed form, such as <code>YES</code> or <code>NO</code>, so the rule can compare it.</li>
<li>A model can give different answers to the same prompt. If decisions must be audited, keep the prompt, the model name, the reply and the time of the call alongside the decision.</li>
</ul>
