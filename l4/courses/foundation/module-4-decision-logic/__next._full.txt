1f:T10fa5,<h1>Module 4: Decision logic</h1>
<p>In this module, you'll learn how to encode <strong>constitutive rules</strong> - legal rules that determine facts, classifications, and eligibility.</p>
<h2 id="learning-objectives">Learning Objectives</h2>
<p>By the end of this module, you will be able to:</p>
<ul>
<li>Distinguish between constitutive rules (decision logic) and regulative rules (obligations)</li>
<li>Express eligibility determinations using DECIDE</li>
<li>Define computations and definitions using MEANS</li>
<li>Write function signatures with GIVEN and GIVETH</li>
<li>Break down complex calculations with WHERE</li>
<li>Write decision logic that reads like legal text</li>
</ul>
<hr>
<h2 id="what-is-decision-logic">What is Decision Logic?</h2>
<h3 id="constitutive-vs-regulative-rules">Constitutive vs Regulative Rules</h3>
<p>Legal systems contain two types of rules:</p>
<p><strong>Regulative rules</strong> (Modules 1 and 6) specify what parties <strong>must</strong>, <strong>may</strong>, or <strong>must not</strong> do:</p>
<ul>
<li>"The applicant <strong>must</strong> submit documentation <strong>within</strong> 30 days"</li>
<li>"The landlord <strong>may</strong> terminate the lease if rent is unpaid"</li>
<li>"The seller <strong>shall not</strong> disclose confidential information"</li>
</ul>
<p><strong>Constitutive rules</strong> (this module) determine <strong>facts</strong>, <strong>classifications</strong>, and <strong>eligibility</strong>:</p>
<ul>
<li>"An applicant <strong>is eligible</strong> if they are a citizen and over 18"</li>
<li>"The tax owed <strong>is</strong> 20% of gross income minus deductions"</li>
<li>"A person <strong>is a resident</strong> if they have lived here for 183 days or more"</li>
</ul>
<p>In L4, we express constitutive rules as <strong>decision logic</strong> using functions. <a href="/l4/concepts/legal-modeling/constitutive-vs-regulative">Definitions and duties</a> explains why L4 keeps the two kinds apart.</p>
<hr>
<h3 id="every-input-is-declared">Every input is declared</h3>
<p>A decision in L4 can only use what its <code>GIVEN</code> declares, so the signature lists every fact the decision depends on. When someone says "it depends", L4 makes them say on what. <a href="/l4/concepts/language-design/principles#functional-purity">Functional purity</a> explains why this matters for legal rules.</p>
<hr>
<h2 id="working-examples">Working Examples</h2>
<p>All examples in this module are in:</p>
<pre><code class="language-l4-file">-- Module 4: Decision Logic - Complete Examples
-- All examples are validated and use natural language identifiers

IMPORT prelude
IMPORT daydate

-- =======================================
-- SECTION 1: Basic Eligibility Decisions
-- =======================================

-- Simple age-based eligibility
GIVEN `the person's age` IS A NUMBER
GIVETH A BOOLEAN
DECIDE `the person is an adult` IF `the person's age` >= 18

-- Voting eligibility
GIVEN `the person's age` IS A NUMBER
      `is citizen` IS A BOOLEAN
GIVETH A BOOLEAN
DECIDE `the person is eligible to vote` IF
    `the person's age` >= 18
    AND `is citizen`

-- Senior discount qualification
GIVEN `the customer's age` IS A NUMBER
GIVETH A BOOLEAN
DECIDE `qualifies for senior discount` IF
    `the customer's age` >= 65

-- Student status determination
GIVEN `the person's age` IS A NUMBER
      `is enrolled` IS A BOOLEAN
GIVETH A BOOLEAN
DECIDE `the person is a student` IF
    `the person's age` >= 16
    AND `the person's age` &#x3C;= 25
    AND `is enrolled`

-- =======================================
-- SECTION 2: Using DECIDE IF vs DECIDE IS vs MEANS
-- =======================================

-- DECIDE IF: Best for yes/no questions with conditions
GIVEN `the income` IS A NUMBER
GIVETH A BOOLEAN
DECIDE `qualifies for exemption` IF `the income` &#x3C; 10000

-- DECIDE IS: Best for classification or value assignment
GIVEN `the income` IS A NUMBER
GIVETH A STRING
DECIDE `the tax bracket` IS
    BRANCH
        IF `the income` &#x3C; 10000 THEN "exempt"
        IF `the income` &#x3C; 50000 THEN "standard"
        OTHERWISE "higher rate"

-- MEANS: Best for computations and definitions
GIVEN `the income` IS A NUMBER
GIVETH A STRING
`the income category` MEANS
    BRANCH
        IF `the income` &#x3C; 20000 THEN "low"
        IF `the income` &#x3C; 80000 THEN "medium"
        OTHERWISE "high"

-- =======================================
-- SECTION 3: Tax and Financial Calculations with WHERE
-- =======================================

-- Simple tax calculation
GIVEN `the gross income` IS A NUMBER
      `the tax rate` IS A NUMBER
GIVETH A NUMBER
`the tax owed` MEANS
    `the taxable income` * `the tax rate`
    WHERE
        `the standard deduction` MEANS 12000
        `the taxable income` MEANS
            IF `the gross income` > `the standard deduction`
            THEN `the gross income` - `the standard deduction`
            ELSE 0

-- Progressive tax with multiple brackets
GIVEN `the income` IS A NUMBER
GIVETH A NUMBER
`the income tax owed` MEANS
    `tax on first bracket` + `tax on second bracket` + `tax on third bracket`
    WHERE
        `tax on first bracket` MEANS
            `amount in first bracket` * 0.10

        `tax on second bracket` MEANS
            `amount in second bracket` * 0.20

        `tax on third bracket` MEANS
            `amount in third bracket` * 0.30

        `amount in first bracket` MEANS
            BRANCH
                IF `the income` &#x3C;= 10000 THEN `the income`
                OTHERWISE 10000

        `amount in second bracket` MEANS
            BRANCH
                IF `the income` &#x3C;= 10000 THEN 0
                IF `the income` &#x3C;= 50000 THEN `the income` - 10000
                OTHERWISE 40000

        `amount in third bracket` MEANS
            BRANCH
                IF `the income` &#x3C;= 50000 THEN 0
                OTHERWISE `the income` - 50000

-- Net income calculation
GIVEN `the gross income` IS A NUMBER
      `the expenses` IS A NUMBER
GIVETH A NUMBER
`the net income` MEANS
    `the gross income` - `the total deductions`
    WHERE
        `the standard deduction` MEANS
            IF `calculated deduction` >= 1000
            THEN `calculated deduction`
            ELSE 1000

        `calculated deduction` MEANS `the gross income` * 0.10

        `the total deductions` MEANS
            `the standard deduction` + `the expenses`

-- Compound interest with a named helper
GIVEN `the principal` IS A NUMBER
      `the annual rate` IS A NUMBER
      `the years` IS A NUMBER
GIVETH A NUMBER
`the compound interest` MEANS
    `the principal` * EXPONENT `the growth factor` `the years`
    WHERE
        `the growth factor` MEANS 1 + `the annual rate`

-- Loan payment with several helpers
GIVEN `the loan amount` IS A NUMBER
      `the annual rate` IS A NUMBER
      `the term in months` IS A NUMBER
GIVETH A NUMBER
`the monthly payment` MEANS
    `the loan amount` *
    (`the monthly rate` * `the compound factor`) /
    (`the compound factor` - 1)
    WHERE
        `the monthly rate` MEANS `the annual rate` / 12
        `the compound factor` MEANS EXPONENT (1 + `the monthly rate`) `the term in months`

-- =======================================
-- SECTION 4: Structured Entity Examples
-- =======================================

DECLARE Person HAS
    name IS A STRING
    age IS A NUMBER
    citizenship IS A STRING
    `annual income` IS A NUMBER
    `criminal record` IS A BOOLEAN

-- Comprehensive benefit eligibility
GIVEN `the applicant` IS A Person
GIVETH A BOOLEAN
DECIDE `the applicant is eligible for benefit` IF
    `the applicant is a qualifying resident`
    AND `the applicant is of age`
    AND `the applicant meets income threshold`
    AND NOT `the applicant is disqualified`
    WHERE
        `the applicant is a qualifying resident` MEANS
            `the applicant`'s citizenship = "citizen"

        `the applicant is of age` MEANS
            `the applicant`'s age >= 21
            AND `the applicant`'s age &#x3C; 65

        `the applicant meets income threshold` MEANS
            `the applicant`'s `annual income` &#x3C; 30000

        `the applicant is disqualified` MEANS
            `the applicant`'s `criminal record`

-- Tax bracket determination with record
GIVEN `the taxpayer` IS A Person
GIVETH A STRING
DECIDE `the taxpayer's bracket` IS
    BRANCH
        IF `the taxpayer`'s `annual income` &#x3C; 10000 THEN "exempt"
        IF `the taxpayer`'s `annual income` &#x3C; 50000 THEN "standard"
        IF `the taxpayer`'s `annual income` &#x3C; 100000 THEN "higher"
        OTHERWISE "top rate"

-- =======================================
-- SECTION 5: Multi-Factor Decisions
-- =======================================

-- Loan approval decision
GIVEN `the income` IS A NUMBER
      `the credit score` IS A NUMBER
      `the loan amount` IS A NUMBER
GIVETH A BOOLEAN
DECIDE `the loan is approved` IF
    `income requirement is met`
    AND `credit score is sufficient`
    AND `debt to income ratio is acceptable`
    WHERE
        `income requirement is met` MEANS
            `the income` >= `the loan amount` * 0.3

        `credit score is sufficient` MEANS
            `the credit score` >= 650

        `debt to income ratio is acceptable` MEANS
            `the loan amount` &#x3C;= `the income` * 4

-- Insurance premium calculation
GIVEN `the insured age` IS A NUMBER
      `the coverage amount` IS A NUMBER
      `is smoker` IS A BOOLEAN
GIVETH A NUMBER
`the annual premium` MEANS
    `the base premium` * `the age factor` * `the smoking factor`
    WHERE
        `the base premium` MEANS
            `the coverage amount` * 0.001

        `the age factor` MEANS
            BRANCH
                IF `the insured age` &#x3C; 30 THEN 1.0
                IF `the insured age` &#x3C; 50 THEN 1.5
                OTHERWISE 2.0

        `the smoking factor` MEANS
            IF `is smoker` THEN 1.5 ELSE 1.0

-- =======================================
-- SECTION 6: Real-World Contract Scenarios
-- =======================================

-- Late payment penalty calculation
GIVEN `the principal amount` IS A NUMBER
      `days overdue` IS A NUMBER

<h2 id="basic-decisions-with-decide">Basic Decisions with DECIDE</h2>
<h3 id="eligibility-determinations">Eligibility Determinations</h3>
<p>The most common legal decision: "Does X qualify?"</p>
<pre><code class="language-l4">GIVEN `the applicant` IS A Person
GIVETH A BOOLEAN
DECIDE `the applicant is eligible for benefits` IF
    `the applicant is a citizen`
    AND `the applicant's age` >= 18
    AND NOT `the applicant is disqualified`
</code></pre>
<p>Use <strong>DECIDE IF</strong> for yes/no questions, with the conditions after <code>IF</code> joined by <code>AND</code>, <code>OR</code> and <code>NOT</code>.</p>
<h3 id="classification-rules">Classification Rules</h3>
<p>"What category does X fall into?"</p>
<p>Use <code>BRANCH</code> for multi-way classification decisions:</p>
<pre><code class="language-l4">GIVEN `the income` IS A NUMBER
GIVETH A STRING
DECIDE `the tax bracket` IS
    BRANCH
        IF `the income` &#x3C; 10000 THEN "low"
        IF `the income` &#x3C; 50000 THEN "medium"
        OTHERWISE "high"
</code></pre>
<p><code>BRANCH</code> reads like a legal test with several conditions, and avoids the indentation problems of nested <code>IF</code>s (<a href="/l4/courses/foundation/module-3-control-flow#multi-way-decisions-with-branch">Module 3</a>).</p>
<h3 id="decide-is-vs-decide-if">DECIDE IS vs DECIDE IF</h3>
<p><code>DECIDE `the person is an adult` IF age >= 18</code> and <code>DECIDE `the person is an adult` IS age >= 18</code> mean the same. Use <code>IF</code> when the rule reads like a legal condition, and <code>IS</code> with a <code>BRANCH</code> for a classification, as above.</p>
<hr>
<h2 id="computations-with-means">Computations with MEANS</h2>
<h3 id="defining-calculations">Defining Calculations</h3>
<p>Use <strong>MEANS</strong> to define computed values and formulas:</p>
<pre><code class="language-l4">GIVEN `the gross income` IS A NUMBER
      `the deductions` IS A NUMBER
GIVETH A NUMBER
`the taxable income` MEANS
    `the gross income` - `the deductions`
</code></pre>
<h3 id="decide-vs-means">DECIDE vs MEANS</h3>
<p>Both define things. Use whichever reads better:</p>
<table>
<thead>
<tr>
<th>Use DECIDE when...</th>
<th>Use MEANS when...</th>
</tr>
</thead>
<tbody>
<tr>
<td>Asking a yes/no question</td>
<td>Defining a value or computation</td>
</tr>
<tr>
<td>Determining classification/status</td>
<td>Stating what something equals</td>
</tr>
<tr>
<td>Condition reads naturally with IF</td>
<td>Definition reads naturally with =</td>
</tr>
</tbody>
</table>
<p><code>DECIDE `the person is an adult` IF age >= 18</code> reads more naturally than <code>`the person is an adult` MEANS age >= 18</code>, and <code>`the net income` MEANS `gross income` - `expenses`</code> more naturally than the same with <code>DECIDE … IS</code>. All four are valid.</p>
<hr>
<h2 id="function-signatures">Function Signatures</h2>
<p>Every decision or computation has a <strong>signature</strong> that declares:</p>
<ol>
<li><strong>Inputs</strong> (<code>GIVEN</code>): what information is needed, one name and type per input</li>
<li><strong>Output</strong> (<code>GIVETH</code>): what type of result is produced</li>
</ol>
<table>
<thead>
<tr>
<th>The rule is a...</th>
<th>Typical signature</th>
</tr>
</thead>
<tbody>
<tr>
<td>Yes/no decision</td>
<td><code>GIVEN `the person` IS A Person</code> and <code>GIVETH A BOOLEAN</code></td>
</tr>
<tr>
<td>Classification</td>
<td><code>GIVEN `the entity` IS AN Entity</code> and <code>GIVETH A STRING</code>, or an enum</td>
</tr>
<tr>
<td>Computation</td>
<td><code>GIVEN `the income` IS A NUMBER</code> and <code>GIVETH A NUMBER</code></td>
</tr>
</tbody>
</table>
<p>A rule can have several inputs. List each on its own line, aligned under the first:</p>
<pre><code class="language-l4">GIVEN `the days since the decision` IS A NUMBER
      `the appeal period in days` IS A NUMBER
GIVETH A BOOLEAN
DECIDE `the appeal is in time` IF
    `the days since the decision` AT MOST `the appeal period in days`
</code></pre>
<p>Callers pass the arguments in the order of the <code>GIVEN</code> lines: <code>`the appeal is in time` 10 21</code> is <code>TRUE</code>. Other result types include <code>GIVETH A Person</code> (a record), <code>GIVETH A LIST OF NUMBER</code> and <code>GIVETH A MAYBE NUMBER</code>.</p>
<p>L4 can usually work out the result type on its own, so <code>GIVETH</code> may be left out. Write it anyway: it documents the rule, and it gives clearer error messages when the body does not match.</p>
<hr>
<h2 id="breaking-down-complex-logic-with-where">Breaking Down Complex Logic with WHERE</h2>
<h3 id="local-helper-calculations">Local Helper Calculations</h3>
<p>Legal formulas often involve intermediate calculations. Use <strong>WHERE</strong> to break them down:</p>
<pre><code class="language-l4">GIVEN `the principal` IS A NUMBER
      `the annual rate` IS A NUMBER
      `the years` IS A NUMBER
GIVETH A NUMBER
`the compound interest` MEANS
    `the principal` * EXPONENT `the growth factor` `the years`
    WHERE
        `the growth factor` MEANS 1 + `the annual rate`
</code></pre>
<p>(<code>EXPONENT base power</code> is L4's built-in exponentiation function.)</p>
<p><strong>Benefits:</strong></p>
<ul>
<li>Makes complex formulas readable</li>
<li>Gives meaningful names to intermediate values</li>
<li>Matches how legal documents explain calculations</li>
</ul>
<h3 id="multiple-where-definitions">Multiple WHERE Definitions</h3>
<pre><code class="language-l4">GIVEN `the loan amount` IS A NUMBER
      `the annual rate` IS A NUMBER
      `the term in months` IS A NUMBER
GIVETH A NUMBER
`the monthly payment` MEANS
    `the loan amount` *
    (`the monthly rate` * `the compound factor`) /
    (`the compound factor` - 1)
    WHERE
        `the monthly rate` MEANS `the annual rate` / 12
        `the compound factor` MEANS EXPONENT (1 + `the monthly rate`) `the term in months`
</code></pre>

<h3 id="optional-values-with-maybe">Optional Values with MAYBE</h3>
<p>Legal data is often incomplete: a contract may or may not have a termination date; notice may or may not have been given. L4 models "a value that might be absent" with the <strong>MAYBE</strong> type:</p>
<ul>
<li><code>MAYBE DATE</code> means "a date, or nothing"</li>
<li><code>NOTHING</code> is the value when it's absent</li>
<li><code>JUST value</code> wraps a value when it's present</li>
</ul>
<p>You inspect a MAYBE with <code>CONSIDER</code>, handling both cases:</p>
<pre><code class="language-l4">CONSIDER `the contract`'s `the termination date`
WHEN NOTHING THEN TRUE                 -- no termination date: contract is open-ended
WHEN JUST `the end date` THEN ...      -- there is one: use `the end date`
</code></pre>
<p>The type system forces you to say what happens in <strong>both</strong> cases—no "null pointer" surprises, and no silently ignored edge case.</p>
<h3 id="working-with-dates">Working with Dates</h3>
<p>L4 has a built-in <code>DATE</code> type. With <code>IMPORT daydate</code>, you can construct dates as <code>Date day month year</code> (for example, <code>Date 15 4 2024</code>) and compare them directly with <code>&#x3C;</code>, <code>>=</code>, and so on.</p>
<p>To count the days between two dates, convert them to serial day numbers with <code>DATE_SERIAL</code>:</p>
<pre><code class="language-l4">GIVEN `the first date` IS A DATE
      `the second date` IS A DATE
GIVETH A NUMBER
`the days between` MEANS
    DATE_SERIAL `the second date` - DATE_SERIAL `the first date`
</code></pre>

    `the contract is active`
    AND `the party has given sufficient notice`
    WHERE
        `the contract is active` MEANS
            `today` >= `the contract`'s `the effective date`
            AND CONSIDER `the contract`'s `the termination date`
                WHEN NOTHING THEN TRUE
                WHEN JUST `the end date` THEN `today` &#x3C; `the end date`

        `the party has given sufficient notice` MEANS
            CONSIDER `the party`'s `notice was given on`
            WHEN NOTHING THEN FALSE
            WHEN JUST `the notice date` THEN
                `the days between` `the notice date` `today` >= `the contract`'s `the notice period in days`
</code></pre>
<p>Try it with the test data from the examples file:</p>
<pre><code class="language-l4">`the open-ended contract` MEANS Contract (Date 1 1 2024) NOTHING 30
`the party with notice` MEANS `Contract Party` "Acme Ltd" (JUST (Date 1 3 2024))

#EVAL `the party may terminate` `the open-ended contract` `the party with notice` (Date 15 4 2024)
-- Result: TRUE
</code></pre>

<h2 id="exercises">Exercises</h2>
<h3 id="exercise-1-simple-eligibility">Exercise 1: Simple Eligibility</h3>
<p>Write a decision that determines if a person qualifies for a senior discount (age 65 or older):</p>
<pre><code class="language-l4">GIVEN `the person's age` IS A NUMBER
GIVETH A BOOLEAN
DECIDE `qualifies for senior discount` IF
    -- Your code here
</code></pre>
<details>
<summary>Solution</summary>
<pre><code class="language-l4">GIVEN `the person's age` IS A NUMBER
GIVETH A BOOLEAN
DECIDE `qualifies for senior discount` IF
    `the person's age` >= 65

#EVAL `qualifies for senior discount` 70
#EVAL `qualifies for senior discount` 50
</code></pre>
</details>
<h3 id="exercise-2-multi-condition-eligibility">Exercise 2: Multi-Condition Eligibility</h3>
<p>A person qualifies for a student loan if they:</p>
<ul>
<li>Are between 18 and 35 years old</li>
<li>Are enrolled in an accredited institution</li>
<li>Have no prior loan defaults</li>
</ul>
<p>Write the decision logic.</p>
<details>
<summary>Solution</summary>
<pre><code class="language-l4">GIVEN `the applicant's age` IS A NUMBER
      `the applicant is enrolled in an accredited institution` IS A BOOLEAN
      `the applicant has prior loan defaults` IS A BOOLEAN
GIVETH A BOOLEAN
DECIDE `the applicant qualifies for a student loan` IF
    `the applicant is of eligible age`
    AND `the applicant is enrolled in an accredited institution`
    AND NOT `the applicant has prior loan defaults`
    WHERE
        `the applicant is of eligible age` MEANS
            `the applicant's age` >= 18
            AND `the applicant's age` &#x3C;= 35

#EVAL `the applicant qualifies for a student loan` 25 TRUE FALSE
#EVAL `the applicant qualifies for a student loan` 40 TRUE FALSE
#EVAL `the applicant qualifies for a student loan` 25 TRUE TRUE
</code></pre>
</details>
<h3 id="exercise-3-calculation-with-where">Exercise 3: Calculation with WHERE</h3>
<p>Write a computation for net income that:</p>
<ul>
<li>Starts with gross income</li>
<li>Subtracts standard deduction (calculated as 10% of gross, minimum $1000)</li>
<li>Subtracts itemized deductions</li>
</ul>
<p>Use WHERE to break down the calculation clearly.</p>
<details>
<summary>Solution</summary>
<pre><code class="language-l4">GIVEN `the gross income` IS A NUMBER
      `the itemized deductions` IS A NUMBER
GIVETH A NUMBER
`the net income` MEANS
    `the gross income` - `the standard deduction` - `the itemized deductions`
    WHERE
        `the standard deduction` MEANS
            IF `the calculated deduction` >= 1000
            THEN `the calculated deduction`
            ELSE 1000

        `the calculated deduction` MEANS
            `the gross income` * 0.10

#EVAL `the net income` 100000 5000
#EVAL `the net income` 8000 500
</code></pre>
</details>

<h2 id="common-mistakes">Common Mistakes</h2>
<h3 id="using-programmer-names">Using Programmer Names</h3>
<pre><code class="language-l4">-- Wrong: Programmer style
GIVEN p IS A Person
GIVETH A BOOLEAN
isEligible p MEANS p.age >= 18 &#x26;&#x26; !p.disqualified

-- Right: Natural language
GIVEN `the person` IS A Person
GIVETH A BOOLEAN
DECIDE `the person is eligible` IF
    `the person`'s age >= 18
    AND NOT `the person`'s disqualified
</code></pre>
